# 配音工作流手动验收清单

本清单用于在真实环境中验证 GPT-SoVITS 配音工作流。自动化测试覆盖了
「场景解析 / 语句改写 / 音频裁剪 / 内容哈希 / 角色库与 zip / 历史对齐 / 队列估算」等纯逻辑
(见 `cargo test -p webgal-ink` 与 `cargo test -p webgal-language-core`),
但以下环节依赖真实 GUI、真实整合包与真实网络端口, 必须手动走一遍。

## 0. 前置条件

- 一份 GPT-SoVITS **v4** 整合包 (含 `api_v2.py`、`runtime\python.exe` 与 v4 权重)。
- 一个 WebGAL 项目 (含 `game/scene/*.txt` 与 `game/vocal/`)。
- 一段 3~10 秒、人声清晰的参考音频 (wav)。

## 1. 后端自动化验证

```bash
cargo test --workspace
cargo check -p webgal-ink
npm run lint:all
```

预期: 全部通过, 无 warning (含 `webgal-ink` 的 `cargo check`)。

## 2. GSOV 进程管理

| 步骤                                 | 预期                                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------------------- |
| 总控台选择整合包目录                 | 自动填充启动方式为「整合包内置运行时」, 路径为 `<root>\runtime\python.exe`, 端口 9880    |
| 点「启动」                           | 状态变为「启动中…」, 日志面板出现 `$ <python> -I api_v2.py ...` 与模型加载输出           |
| 等待模型加载完成                     | 状态变为「就绪」, 总控台顶部与选项卡角标同步更新                                         |
| 切到「外部 Python」并指向 conda 环境 | 启动参数**不含** `-I` (否则会因屏蔽用户级 site-packages 而 `ModuleNotFoundError: click`) |
| 切到「自定义命令」                   | 命令与参数原样执行, Ink 不追加任何参数                                                   |
| 点「停止」                           | 进程优雅退出 (服务端有机会落盘 `tts_infer.yaml`), 状态回到「未启动」                     |
| 退出 Ink                             | GSOV 进程一并退出, 无残留 `python.exe`                                                   |

> 端口被占用时应给出可读错误, 而不是静默卡在「启动中…」。

## 3. 角色库

| 步骤                  | 预期                                                             |
| --------------------- | ---------------------------------------------------------------- |
| 新建角色              | 出现在列表中, id 为名称的 slug (中文保留)                        |
| 添加 4 秒参考音频     | 直接入库, 记录时长/采样率, 内容哈希文件名 `ref_<hash>.wav`       |
| 添加 2 秒参考音频     | **静默**在尾部补静音, 入库后时长 ≥ 3s                            |
| 添加 12 秒参考音频    | 弹出裁剪对话框: 显示波形、自动放置区间、可拖拽、可试听           |
| 裁剪区间拖到 > 10s    | 确认按钮禁用并提示超限                                           |
| 参考文本留空          | 确认按钮禁用 (v4 必需)                                           |
| 再次添加同一文件      | 复用同一 `ref_<hash>.wav`, 不产生副本                            |
| 试听                  | 与角色列表的试听互斥 (同时只有一个在响)                          |
| 导出 zip              | 压缩包含 `character.json` 与 `audio/ref_*.wav`; **不含**模型选择 |
| 导入 zip (另建角色名) | 角色入库, 参考音频落盘; 模型选择为空                             |
| 删除参考音频          | 文件被删除; 若库内其他条目引用同一文件则不删                     |
| 删除角色              | 配置与音频目录一并删除                                           |

## 4. 场景卡配音模式

| 步骤             | 预期                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 选中场景卡       | 选项卡**最左侧**出现**带斜杠的麦克风**                           |
| 点击麦克风       | 变为实心麦克风, 卡片切换为配音模式; 代码内容不变                 |
| 取消选中该卡     | 麦克风按钮消失 (配音模式仍生效, 标签底部有强调色)                |
| 光标移到对话行   | 操作台显示该句配置; 角色/语言/参考音频按场景与历史回填           |
| 光标移到非对话行 | 操作台清空为提示文字, **高度不变** (编辑器不跳动)                |
| 顶栏配音按钮     | 未打开时打开总控台选项卡并把当前场景卡切进配音模式; 已打开时关闭 |
| 未打开总控台时   | 状态栏**不出现**任何 GSOV 文案; 只有总控台选项卡上才有 GSOV 状态 |

### 4.1 总控台是一个选项卡

| 步骤                 | 预期                                                                    |
| -------------------- | ----------------------------------------------------------------------- |
| 点击顶栏配音按钮     | 选项卡栏出现「配音总控台」选项卡并选中, 编辑区被它铺满 (不再是侧边面板) |
| 切到其它选项卡       | 总控台选项卡仍存在, 再次点击可切回                                      |
| 队列有任务时         | 总控台选项卡标题显示待处理 + 运行中数量的角标                           |
| 点击总控台选项卡的 × | 关闭总控台 (等同于退出全局配音模式); 场景卡的配音模式与队列不受影响     |
| 未打开总控台时       | 状态栏不出现任何 GSOV 信息; 打开后才在总控台顶部看到状态与端口          |

### 4.2 提示文本风格

全项目的悬浮提示统一使用原生 `title` 属性 (与场景选项卡的关闭按钮一致),
**不使用** Fluent UI 的 `Tooltip` 组件 (其在 WebView 中会出现背景透明的渲染问题)。
检查点: 悬浮麦克风按钮、角标、历史右键项、参考音频按钮时, 提示都是系统原生样式,
且不会有"背景被置空"的现象。

## 5. 生成与队列

| 步骤                   | 预期                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| 点「测试 x4」          | 任务进入立即队列; 历史新增一条「测试 x4」并自动选中; 显示进度        |
| 生成中再点「生成 x32」 | 进入普通队列; 当前测试任务不被中断, 测试优先于生成                   |
| 连续点 3 次测试        | 三条任务同角色连续执行 (日志中参考音频缓存命中, 不再重载)            |
| 生成中观察总控台       | 待处理/运行中计数正确, 显示估算剩余时间                              |
| 等待完成               | 历史项变为已完成, 可试听; 音频落盘于 `<appdata>\tts\<hash>.wav`      |
| 修改温度后再点「生成」 | 创建**新任务**; 旧历史项不受影响; 应用按钮禁用并提示「当前为新配置」 |
| 选中已完成项           | 应用按钮可用; 测试项同样可应用 (v0.5 不区分)                         |
| 任务进行中点「取消」   | 立即取消 (队列尚未发出请求), 历史项变为已取消                        |
| 服务端报错             | 历史项显示错误文本, 队列继续执行后续任务                             |

## 6. 应用与移除

| 步骤                     | 预期                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------- |
| 点「应用」               | 音频移到 `game/vocal/<角色 id>/<hash>.wav`; 该行出现 `-vocal=<角色 id>/<hash>.wav` |
| 开启自动保存时           | 文件立即落盘, 选项卡无脏标记                                                       |
| 关闭自动保存时           | 编辑器内容更新且出现脏标记, 需手动保存; 卡片提示与磁盘不一致                       |
| 预览播放                 | 刷新预览后该句台词有声                                                             |
| 手动改坏该行后重开配音卡 | 提示「场景可能已被修改」并中止, 不写入                                             |
| 点「移除」               | `-vocal=` 被删除; **音频文件仍在**; 历史记录仍在 (标记为未应用)                    |
| 缓存清理                 | 「缓存与引用」列出缓存; 未引用项可勾选删除; 引用计数来自真实扫描                   |
| 脚本引用不存在的音频     | 列表中列出缺失项 (场景:行号 → 值)                                                  |

## 7. 历史重新对齐与本地变更裁决

| 步骤                                       | 预期                                                 |
| ------------------------------------------ | ---------------------------------------------------- |
| 关闭配音卡 → 在场景中插入几行 → 重开配音卡 | 历史按「对话者 + 内容」精确匹配到新行号              |
| 删除某条显式说话者行                       | 受影响历史项标记为「归属可能已变」, 不静默错配       |
| 删除某句对话                               | 对应历史项标记为「未对齐」并可手动删除               |
| 用外部编辑器改磁盘上的场景文件             | 卡片激活或窗口重新聚焦时弹出裁决对话框               |
| 选择「保留编辑器内容」                     | 编辑器内容不变, 历史按编辑器内容对齐                 |
| 选择「加载磁盘内容」                       | 编辑器被磁盘内容替换, 脏标记清除, 历史重新对齐       |
| 选择「备份后加载磁盘」                     | 生成 `<场景>.ink-backup.txt` 后再加载磁盘内容        |
| 选择「用 git 合并」                        | 打开该场景的差异对比选项卡 (非 git 仓库时该按钮禁用) |

## 8. 已知边界

- **仅本地部署**: 参考音频与权重路径必须是 GSOV 进程所在机器的本地路径, API 没有上传通道。
  容器部署需要自行把项目目录与 `<appdata>` 挂进容器。
- **仅 v4 模型**: 采样步数限 4/8/16/32; `super_sampling` 在 v4 上无效, 界面不暴露。
- **重试未接入队列**: 历史项的「以此参数重试」尚未实现 (右键菜单中的相关项为 v0.6)。
- **缓存清理不支持自动清理**: 为避免误删跨场景引用的文件, 只提供手动确认清理。
