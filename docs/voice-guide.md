# GPT-SoVITS 配音工作流

> **实验性功能**：配音工作流仍在逐步完善和稳定中，界面、接口与数据结构都可能继续调整。
> 遇到问题请连着操作步骤一起反馈，比截图更好定位。

Ink 的配音功能把 **GPT-SoVITS（GSOV）v4** 的推理接入到场景编辑流程里：在配音工作台配置服务与角色，在场景卡的配音编辑模式里逐句生成、试听、应用。

> 当前仅支持 **v4 模型**，且仅支持 **本地部署**（由 Ink 自己拉起 GSOV 进程）。

## 一、准备工作

1. 准备一份 GPT-SoVITS v4 整合包（含 `api_v2.py` 与 `runtime\python.exe`）。
2. 在配音工作台中填写**整合包路径**，Ink 会自动探测运行时并给出默认启动参数。
3. 需要时切换启动方式：

| 启动方式             | 适用场景                  | 说明                                                                                                                                                                                                      |
| -------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 整合包内置运行时     | 默认，推荐                | 使用 `runtime\python.exe`，依赖自包含，会自动加 `-I` 隔离；解释器路径只读                                                                                                                                 |
| 自定义 Python 解释器 | 自建 / 系统 Python        | 直接指定解释器路径；**不加** `-I`：隔离模式会屏蔽用户级 site-packages，而 `click` 等依赖常装在那里                                                                                                        |
| conda 运行环境       | 依赖装在 conda 环境里     | 只选**环境名**（Ink 会扫描本机 conda 环境）。Ink 走 `conda run -n <环境> python`，等于先激活环境再执行 —— 直接调用环境的 `python.exe` **不会**加载激活脚本，环境里装好的 numpy 也会 `ModuleNotFoundError` |
| 自定义命令           | 自己写 bat/ps1 或整条命令 | **整条命令直接输入**（支持引号包裹的路径），切换到该方式时会自动填入"用内置运行时跑控制脚本"的等价命令，按需改一处即可                                                                                    |

4. 点击「启动服务」，工作台页头与底部状态栏会显示 `启动中…` / `就绪`。首次启动需要加载模型（数十秒）。

## 二、角色

角色 = **GSOV 模型 + 参考音频**组合。

- **参考音频**会被拷贝进 Ink 的用户数据目录，不引用原位置；同内容音频自动去重。
- GSOV 要求参考音频时长在 **3~10 秒**：
  - 过短：自动在尾部补静音（静默处理）；
  - 过长：弹出裁剪对话框，展示波形与自动建议区间，由你确认后由后端裁剪。
- **参考文本必填**，且必须与参考音频**逐字一致**。v4 模型在使用声码器时不允许空参考文本，文本不符会让音色跑偏。
- **标签**目前仅用于 Ink 内部整理，后续版本会承载更多语义。
- 参考音频支持试听；角色列表支持搜索、新建、导入/导出 zip。
- **角色列表只展示信息，不提供就地编辑**（一行里塞满输入框会带来很大的认知压力）。点任一角色卡即打开「编辑角色」对话框，名称、ID、星标、启用、两个 GPT-SoVITS 模型、描述与**参考音频编辑列表**都在那里。
- **角色 ID 可以直接编辑**（它同时是配置文件名与 `game/vocal/<id>/` 目录名，改名时 Ink 会一并搬移参考音频目录）。列表顺序按「星标、加入顺序」排列，因此改设置不会让卡片换位置。
- **参考音频列表在三个地方长得完全一样**（「编辑角色」、「选择参考音频」以及从「选择角色」点进角色时）：顶部一行是**搜索框 + 条数 + 「添加参考音频」**，下面是**自己滚动**的列表，每条都能试听、删除。「添加参考音频」在三处打开的是**同一个对话框**，加完留在原地并把新条目选上（补齐语料往往要连着加好几条）。
- 「选择角色」对话框负责**挑选参与配音的角色**（勾选 + 星标 + 导入），**点角色名则打开该角色的「编辑角色」**——只是这一份不显示 GSOV 权重（权重是服务端本机的路径，与"这个角色有哪些参考音频"无关）。
- **导入角色（zip 或清单）后会按名称自动配对 GSOV 模型**：整合包里的权重就是拿这个角色训的，名字通常对得上（`千早爱音` ↔ `爱音-e15.ckpt`）。只有名称**相同或互相包含**时才自动选，名称对不上就留空由你手选 —— 配错比不配更难查（界面看起来已经选好了，音色却不对）。已经选过权重的角色不会被改动。
- 「从清单导入」导入的是整套训练语料，**条数不受限制**；条数较多（超过 300 条）时会先列出"将导入多少条、各角色多少条"，确认后才开始（每段音频都要拷进角色库并逐个规范化，会花时间也会占空间）。过短的音频自动补静音，过长的按静音边界裁剪。

## 三、队列

配音任务**严格串行**执行：GSOV 后端是单进程单 worker，并且持有全局的参考音频缓存，并发请求会互相干扰。

队列分为两类，按此优先级执行：

1. **优先队列** — 默认是测试任务（x4 采样步数），用于快速试参数与试种子；
2. **常规队列** — 默认是生成任务（x32 采样步数），用于产出正式音频。

**优先级是任务自己的属性**，和「测试 / 生成」不是一回事：排队中的任务随时可以改档 —— 记录右侧、取消按钮左边那个箭头图标就是开关（上箭头=提升为优先，下箭头=降为常规），右键菜单里也有。例如把一条生成任务提到优先，它就会插到其他生成任务前面先跑。运行中与已完成的任务不能再改档。

两个队列内部都**按角色分组**：同一角色的任务连续执行，避免服务端反复重载模型（切换权重需要重载底模，代价很高）。

队列列表的顺序就是**将要发生的顺序**：运行中 → 排队中（优先在前、组内按角色） → 已结束（按完成时刻从新到旧）。

进度与剩余时间是**估算**，而且会自己学着变准：

- 按**采样步数分档**（x4 / x8 / x16 / x32 各一套系数，互不污染），每档回归出「固定开销 + 每字耗时」；
- 样本就是那一次请求的**实测响应时间**（发出到返回）；没有样本时用先验（x4 十六字约 3 秒、x32 约 40 秒），**第一个样本回来就会整体纠偏**，攒够三个样本后转为回归；
- **偏高的离群值直接剔除**（超过 `中位数 + 4×MAD`），服务刚启动或刚切换权重后的那个任务也不计入 —— 它包含模型加载，比正常推理高一个量级；
- 样本记在本地，换一次会话接着用。

进度条按预估时间往前走，因此**走满只代表"该好了"**，不代表一定结束；排队中的任务只显示预计耗时。

「取消」对排队中的任务是直接撤下；对**正在推理**的任务则表示"这一条不要了" —— 推理本身没有中断接口，返回的结果会被丢弃，队列继续往下跑。**被取消的任务会从本句历史里移除**（任务队列里仍能看到它已被撤下），而且取消不会动你正在编辑的那套参数。

## 四、配音编辑模式

**未打开配音工作台时，界面上不会出现任何配音痕迹**（场景卡的麦克风按钮也不显示）。

麦克风开关的规则只有三条：

1. 配音工作台**没打开** —— 任何场景卡都不显示；
2. 该场景**已经处于配音编辑模式** —— 始终显示（否则就没法退出）；
3. 其余情况 —— **只在当前选中的那张场景卡**上显示。

因此：打开工作台后**没有任何场景会自动变成配音卡**；切到哪张卡，划线麦克风就在哪张卡上；切到工作台或说明页，划线麦克风就消失。进入配音编辑模式只有一个入口 —— 点当前场景卡上的麦克风；再点一次（此时是实心麦克风）立刻切回普通场景卡。

**该场景还有没跑完的任务时，退出配音卡会先问你一句**：离开只是把界面收起来，任务不会中止（队列是全局的，历史也已落盘），但"看不见进度的等待"很容易被当成卡死。关闭场景选项卡则会真的撤下这些任务，所以那里的提示是另一句话。

配音编辑卡与普通编辑卡**共享同一份文档**，因此修改会立即互相可见。

- 配音编辑卡是**只读编辑器**：它只负责「读场景 + 选语句」，任何编辑都回到普通场景卡完成，因此卡片里不会出现光标插入符，也不会触发自动保存。但**预览同步、语言服务与 git 差异色块照常工作**（移动光标会把预览跳到那一句；「应用」一条配音后，行号旁的差异色块会指出改动了哪一行），关闭自动保存时也能用 `Ctrl+S` 把改动写回磁盘。
- 光标落在对话上时，**整行会被高亮**，下方操作台显示该句的配音配置；移动光标会切换语句，但**操作台高度固定**，不会造成编辑器跳动。
- WebGAL 的语句是**一行一条**（语言核心同样逐行解析），因此判定就是**行号精确匹配**：光标必须落在那条对话所在的行上；停在 `changeBg` 之类的演出语句上时，操作台只清空显示，不影响任何配置与配音记录。
- **种子默认由这条对话派生**：同一条对话每次打开都是同一个种子，因此「测试」与随后的「生成」用的是同一个种子，两次结果可以互相印证。想换种子只有两个入口 —— 「换一个随机种子」按钮，或者选中一条历史记录（连带回填它的参数）。
- **操作台分三段**：第一行「角色 / 语言 / 参考音频」（角色与语言等长，参考音频最长），第二行「文本」，第三行「种子（左）/ 温度 · 语速 · 高级设置（右）」。数值一律用数字输入框，鼠标悬停时输入框右内侧出现**原生步进器**（与设置里的字号输入框一致），按固定刻度走一格（温度 / 语速 / 重复惩罚 0.05，topK 1），取值范围写在标签右侧。
- **「文本」是可以改的，改了就按改过的文本合成**：它默认是场景里的这一句，编辑后点「测试」或「生成」，送进模型的与记录里显示的都会是你改后的文本（选中一条历史记录时回填的是它当时合成的文本）。场景文件本身不会被这句改动影响。
- **「参考音频」点开的是该角色的参考音频列表**：带搜索、可试听、可删除，顶部还能**直接补一条**（打开的就是「编辑角色」里那个添加对话框，加完留在原地）。**没选角色时点它不会有反应** —— 参考音频是角色的东西，选了角色才谈得上挑一条；也不会出现"选完角色它自己弹出来"。
- 操作台高度固定：「高级设置」展开时只有**设置项那一段**滚动，底部的状态行与「测试 / 生成 / 移除 / 应用」始终停在原地。
- 「采样步数」指的是**正式生成**用几档，因此只会被生成记录回填；跑一次测试（固定 x4）不会把面板上的档位带成 x4。
- 历史记录与工作台队列里，**未完成**的任务不显示播放/删除，只显示「改优先级」（箭头图标，仅排队中）与「取消」。
- 角色会依据场景中的 `-figureId` / `-left` 等立绘引用与**角色名**静默匹配（**别名机制已移除**），依据强度依次是「名称/ID 完全相同」→「立绘引用」→「名称**包含**关系」（对话者写成「千早爱音（教室）」、或简称「爱音」，都能对上角色名）。包含关系出现同等强度的多个候选时**不猜**（宁可没选中，也不让整段对话用错音色）。旁白会沿用同场景上一条旁白所选的角色。匹配结果可以手动更改，更改后会作为该场景的覆盖被记住。
- 工作台角色库的「选择角色」只是**打开挑选对话框**：里面显示的就是当前勾选状态，改一个生效一个；什么都不改地关掉，一切照旧（它不会先替你清空选择）。在那里**点角色名**会打开该角色的「编辑角色」，只是不显示 GSOV 权重 —— 站在挑选对话框里想点开一个角色，通常就是为了补它的参考音频。
- 只有**已启用**的角色参与匹配：如果某条对话一直匹配不上，先确认该角色在「选择角色」里是勾选状态。
- **配音参数的编辑永远不被禁用**：一旦你改动了任意参数（采样步数除外 —— 它只决定这一次生成的质量档位），该配置就被视为**新的配置**，不会影响已有配音记录。此时「测试」「生成」会创建新任务，「应用」按钮不可用，「移除」按钮的含义是**移除当前语句的配音引用**（与记录无关）。操作台下方的状态行会写明当前是「新配置」还是「已生成」。
- 右键配音记录可以应用、在文件夹中打开、导出、**复制种子**、以此参数重试、取消、删除，以及删除本句的批量记录。
- **历史是按"当前这一句对话"组织的**：换一句对话就换一批记录（批量删除也只作用于这一句），不会出现"左右两边说的不是同一件事"。未能对齐到任何语句的残留记录会在列表下方单独列出并提供清理入口。
- **历史会存盘，关掉配音卡、关掉场景选项卡、甚至关掉 Ink 再打开都不丢**：重新打开时按「对话者 + 内容」把每条记录重新对齐到当前场景的行号。对齐不上的记录会明确列在"未能对齐"里，不会猜着配到别的对话上。
- 记录里的 **`响应` = 这一次请求的实测往返时间**（也就是这个任务真正花了多久）。
- 关闭自动保存时，配音卡里按 `Ctrl+S` 同样能把改动写回磁盘；开着实时预览时，移动光标会同步预览到那一句。
- 配音卡（只读）里 **`Ctrl+Z` 撤销、`Ctrl+Y` / `Ctrl+Shift+Z` 重做**同样可用：「应用」一条配音、或者裁决时"加载磁盘内容"，都可以直接撤回去（撤销后按自动保存设置落盘）。

### 配音工作台

配音工作台是**一个普通选项卡**（与场景文件、文本预处理、差异比较同一条选项卡栏），因此拖拽、关闭、切换的行为与其它选项卡完全一致。顶栏的配音按钮负责打开/聚焦它；关闭选项卡即退出配音功能。

页面结构：

```
┌ 页头: 标题 · 服务状态                [启动服务] [帮助] ┐
├ 左栏: 启动方式 / 合成设置 ┬ 右栏: 队列 / 日志        ┤
└ 角色库 (占满剩余高度, 内部滚动)                      ┘
```

- **左栏分两页**：「启动方式」放整合包目录、启动方式与对应的解释器/命令；「合成设置」放默认语言。字段多时分页比堆成一长条更好 —— 一长条就必须滚动，而滚动会把「启动服务」推离视野。两栏高度是**固定**的，切换分页不会让下方角色库一放一缩。
- **整合包目录只有一个文件夹按钮**：还没选过时点击进入选择，已选过时点击在文件管理器中打开。因此不需要额外的「选择…」按钮。
- **第二项随启动方式变化**：整合包运行时显示只读解释器路径；Conda 显示环境下拉（**没有**文件夹图标）；Python 显示路径 + 文件夹图标；自定义命令显示整条命令。
- **启动方式是四选一**：「整合包运行时 / Python / Conda / 自定义命令」。服务**启动中或已就绪**时「启动方式」这一页整体锁定 —— 改了也作用不到已经拉起来的进程上，只会让人以为改动生效了；停止服务后即可修改。
- 绑定地址与端口不展示：它们是给"同一台机器上另开一个服务"准备的，正常使用永远用默认值。
- 「启动服务」与「帮助」在页头右上角，与标题同行。服务启动过程中「停止服务」**始终可用** —— 路径填错时要能立刻停下。
- 右栏是**运行状态**（队列 / 日志两页）：队列页提供清理缓存与清空已完成任务；日志页提供「导出日志」。
- **关闭工作台会顺手停掉 GSOV 服务**（工作台就是这个功能的开关，没必要让一个几 GB 的推理进程继续占着显存与端口）。停止需要等进程收尾，这期间底部状态栏显示 `GSOV: 停止中…`，停完才收起。还有任务没跑完时，关闭工作台会先问你一句 —— 退出的是配音模式，**历史记录不会丢**。
- GSOV 的连接状态只在**编辑器底部状态栏**显示，且只在工作台选项卡存在时出现（`停止中…` 这一项会一直留到停完）；未使用配音功能时界面上不出现任何配音相关信息。
- 「帮助」会打开一个独立的说明选项卡，方便与工作台对照阅读。

### 对话框

全项目的对话框共用同一套外壳：固定尺寸（不随内容自动缩放）、标题栏 + 可滚动主体 + 底部操作区，主操作在右下角、次要操作在左下角。内容超出时是**内容区滚动**，而不是整个面板变形。对话框可以叠加（例如「选择参考音频」之上再开「添加参考音频」），此时 `Esc` 只关闭**最上层**的那一个。

导入角色（zip 与训练切分产物）都在「选择角色」对话框里：「导入角色」导入单个 zip；「从清单导入」分别选择**清单文件**（`.list`）与**音频目录**。两者分开选是刻意的 —— 切分流程常把清单与音频放在不同位置，由你明确指定比自动猜测可靠。清单里的条数**没有上限**，但超过 300 条时会先列出"将导入多少条、各角色多少条"让你确认（每条都会拷贝进角色库并规范化，量大就要花时间和空间）。

### 选项卡栏

所有选项卡（场景文件、文本预处理、差异比较、使用说明）都在同一条选项卡栏里，可以**任意拖拽重排**，不同类型可以交错排布。新打开的选项卡会插在当前选项卡之后；关闭活动选项卡后会激活它右侧的邻居。中键点击选项卡等同于关闭。

## 五、应用与移除

- **应用**：把生成结果移动到 `game/vocal/<角色 id>/<音频哈希>.wav`，并在**编辑器里**把该行的 `-vocal=` 改成指向它 —— 改动立刻出现在编辑器中，和你自己敲了这一行没有区别。是否落盘完全跟随**自动保存**设置：开启时立即写盘且不留脏标记，关闭时留下脏标记等你保存。
  配音流程自己不会去写文件：它只让后端把**那一行**改写好，再由编辑器替换进文档。因此不会出现"文件变了、编辑器没变"，也不会因为自己写盘而弹出「场景文件已被外部修改」。
- **移除**：只清除当前语句的 `-vocal=`，**不删除音频文件，也不清配音记录**。因为同一段音频可能被其他语句甚至其他场景引用（你可能会复制带配音的对话行）。
- 缓存音频的清理是**独立操作**：配音工作台可以列出未被任何场景引用的缓存文件，由你确认后删除。

## 六、重新打开场景卡

配音记录**存在本地**（按场景路径存一份，见 `<用户数据目录>/voice-history/`），关掉配音卡、关掉场景选项卡、甚至重启 Ink 都还在。重新打开时 Ink 会：

1. 先检测磁盘文件是否被外部修改。若是，会先请你裁决：
   - **保留编辑器当前内容**：把编辑器里的这一份**写回磁盘**，此后以它为准（不会再来问第二遍）；
   - 丢弃当前内容并加载磁盘内容；
   - 用 git 合并（打开独立页面）；
   - 另存为副本后再加载磁盘内容；
   - 按 `Esc` 表示暂不决定：谁也不动，但同一个磁盘版本不会再反复弹窗。
2. 把配音记录**重新对齐**到当前的对话列表，分三层，且只做可信匹配：
   - 按「对话者 + 内容」**精确匹配**（唯一完全可信的一层，重复台词按出现顺序依次消费）；
   - 对剩下的条目做**保序匹配**（LCS：插入/删除/移动造成的整体偏移）；
   - 仍匹配不上的列为「未能对齐」，在历史列表下方单独给出，**不猜**。
3. 顺带按脚本重算每条记录的「已应用」标记（判据是该行的 `-vocal=` 是否正指向这条记录的音频）—— 你在普通编辑器里删掉过 `-vocal=` 的话，标记会跟着变回未应用。

上一版把没跑完的任务留在历史里，重开时会永远显示"生成中"；这类记录在载入时直接丢掉（它们本来也没有音频），失败记录则保留，方便回看报错。

因此：**改动越大，能对齐的记录越少**，但已经写进脚本的 `-vocal=` 与磁盘上的音频文件永远不受影响。

## 七、常见问题

- **启动失败**：查看工作台的运行日志。常见原因是整合包路径不对、端口被占用，或者外部 Python 缺少依赖（`ModuleNotFoundError` 时改用整合包内置运行时）。
- **报错说找不到 NLTK 资源**（例如 `Resource averaged_perceptron_tagger_eng not found`）：这是整合包环境里缺数据文件，不是 Ink 的问题。在整合包所用的 Python 环境里执行 `python -m nltk.downloader averaged_perceptron_tagger_eng`（按报错里的资源名替换），然后重试即可。配音记录里的报错**点一下就能看到全文**，并且会附上这条命令。
- **生成很慢**：确认是 CPU 还是 GPU 推理。CPU 上 x32 的一句中长对话可能需要数分钟，建议先用 x4 测试确认参数与种子，再生成。
- **音色不对**：检查参考文本是否与音频逐字一致；检查参考音频是否在 3~10 秒且人声清晰。
- **某句话没有自动匹配到角色**：匹配依据依次是「角色名 / 角色 ID 完全相同」→「立绘引用」→「名称**包含**关系」（「千早爱音（教室）」「爱音」都能对上「千早爱音」）。既不相等也不互相包含的称呼（例如「小爱」）**不会**被猜测性地匹配 —— 手动选一次即可，这个场景会记住。也先确认该角色在「选择角色」里是勾选状态（只有已启用的角色参与匹配）。
- **配音记录里没有想要的记录了**：记录是按场景文件存的，换了项目目录（或把场景文件移走）就会读不到；历史列表下方的「未能对齐」里也可能有它 —— 那是场景改动太大导致行号对不上，重新对齐或手动删除即可。
- **导入的角色没有自动配上模型**：自动配对只在名称相同或互相包含时生效（`千早爱音` ↔ `爱音`）。权重文件名与角色名差得远时（例如 `anon` ↔ `千早爱音`）需要到「编辑角色」里手选一次。
- **生成结果有电音/杂音**：提高采样步数，或调整温度与重复惩罚。
