# GPT-SoVITS 配音工作流

> **实验性功能**：配音工作流还在逐步完善中，可能还有一些没被发现的问题。
> 遇到异常或者有想改进的地方，欢迎到 [GitHub Issues](https://github.com/fltLi/webgal-lsp/issues)
> 反馈 —— 附上操作步骤与报错原文最好定位。

让本机的 GPT-SoVITS v4 替角色念台词：在**配音工作台**里把服务与角色准备好，再到**配音卡**上逐句试听、生成、写回脚本。

> 目前只支持 v4 模型，并且只支持本地部署（由 Ink 自己拉起 GPT-SoVITS 进程）。

## 一、把服务跑起来

打开配音工作台（顶栏的配音按钮），填上 **GPT-SoVITS 整合包路径**，点「启动服务」。首次启动要加载模型，**等几十秒**，状态从 `启动中…` 变成 `就绪` 就可以用了。

启动方式默认用整合包自带的运行时，一般不用改；依赖装在 conda 环境里就选 Conda，用自己的 Python 就选 Python，想自己写命令就选自定义命令。这些配置在服务运行期间是锁定的，改之前先「停止服务」。

> 起不来或者跑着出错，先看工作台右栏的**日志**；配音记录里的报错点一下就能看到全文。

## 二、准备角色

一个角色 = **一套 GPT-SoVITS 权重 + 一批参考音频**。参考音频决定音色，挑一段 3~10 秒、干净清晰的人声最好；**参考文本必须与音频逐字一致**，对不上音色就会跑偏。

- 已经训练好的角色：在「选择角色」里用「导入角色」（zip）或「从清单导入」（训练的切分产物）。导入后会按名称自动配好权重，名称对不上时到「编辑角色」里手选一次即可。
- 从零开始：新建角色，再往里加参考音频。时长不合适的音频会自动补静音，或者弹出裁剪框让你确认一段。

## 三、在配音卡上配一句

打开工作台后，当前场景卡的选项卡上会出现一个**划线麦克风**——点它进入配音卡，再点一次（变实心）回到普通场景卡。没打开工作台时，界面上不会出现任何配音痕迹。

光标停在哪句对话上，编辑器就整行高亮，下方的操作台显示这一句的配置：角色、语言、参考音频、文本、种子、温度、语速，以及收在「高级设置」里的 topK / topP / 重复惩罚 / 采样步数。「文本」可以直接改，改完点测试或生成，送进模型的就是改后的文本，场景文件本身不受影响。

**测试还是生成？** 两者跑的是同一个模型，区别只在采样步数：**「测试 x4」快，用来试参数和种子**；**「生成 x32」慢，用来产出正式音频**。建议先用测试挑好种子和语速，满意了再生成。种子默认跟着这句对话走 —— 同一条对话每次都是同一个种子，所以测试和生成的结果对得上；想换就点旁边的换种子按钮，或者选中一条历史记录把它当时的参数一起捞回来。

角色会**自动匹配**：角色名与对话者对得上（完全相同，或一方包含另一方）就自动选中，对不上就手动选一次，选过之后这个场景会记住。

选中一条记录后，「应用」把它写进脚本（这一行的 `-vocal=`），「移除」只去掉这一句的配音引用，不删音频也不清记录。右边是按**当前这一句**组织的历史：可以试听、删除，右键还有导出音频、复制种子、以此参数重试等。

## 四、让它把整段跑完

任务**一条一条串行执行**，分两档：测试进「优先」，生成进「常规」。排队中的任务右侧有一个箭头图标可以改档（提到优先就先跑），右键菜单里也有。

进度和剩余时间是**估算**，你实际跑出来的几次会让它越来越准。**CPU 上 x32 一句可能要几分钟**，这是正常的；想快就用测试那档。

任务都列在工作台右栏的「队列」里，运行中和排队中的随时可以取消（正在推理的那一条要等它返回后丢弃结果 —— 推理本身没有中断接口）。队列页里还有清理缓存音频、清空已完成任务的入口。

## 五、关掉与重开

关闭配音工作台会**一并停掉 GSOV 服务**（停止期间状态栏显示 `停止中…`）；还有任务没跑完时会先问你一句。

关掉配音卡不会丢东西：记录存在本地，重新打开场景卡时会自动对回原来的位置；对不上的会单独列出来，不会猜着配到别的对话上。如果场景在外部被改过，重开时会先请你决定保留哪一份，然后再把记录对齐过去。
