# GPT-SoVITS 配音工作流

> **实验性功能**：配音工作流仍在逐步完善和稳定中，界面与行为都可能继续调整，
> 也可能还有一些没被发现的问题。使用中遇到异常，或者有想改进的地方，
> 欢迎到 [GitHub Issues](https://github.com/fltLi/webgal-lsp/issues) 反馈 ——
> 请尽量附上操作步骤与报错原文，比截图更好定位。

Ink 的配音功能把 **GPT-SoVITS v4** 接进场景编辑流程：在**配音工作台**里准备服务与角色，在场景卡的**配音编辑模式**里逐句试听、生成、应用。

> 目前只支持 **v4 模型**，并且只支持**本地部署**（由 Ink 自己拉起 GPT-SoVITS 进程）。

## 一、准备工作

1. 准备一份 GPT-SoVITS v4 整合包（含 `api_v2.py` 与 `runtime\python.exe`）。
2. 打开配音工作台，填写**整合包路径**。Ink 会探测其中的运行时并给出默认启动参数。
3. 需要时切换**启动方式**：

| 启动方式     | 适用场景              | 说明                                                                                 |
| ------------ | --------------------- | ------------------------------------------------------------------------------------ |
| 整合包运行时 | 默认，推荐            | 用整合包自带的 `runtime\python.exe`，依赖自包含，不需要额外配置                      |
| Python       | 自建的 Python 环境    | 直接指定解释器路径                                                                   |
| Conda        | 依赖装在 conda 环境里 | 只选环境名；Ink 会先激活环境再执行，因此环境里装好的依赖能被正确加载                 |
| 自定义命令   | 自己写 bat / ps1      | 整条命令直接输入；切过来时会自动填好一条"用整合包运行时跑控制脚本"的等价命令，按需改 |

4. 点「启动服务」。首次启动要加载模型，**需要等几十秒**，状态会从 `启动中…` 变成 `就绪`。

> 上面这些配置在服务运行时是锁定的，想改先「停止服务」。

## 二、角色

一个角色 = **一套 GPT-SoVITS 权重 + 一批参考音频**。

- **参考音频**会被复制进 Ink 的用户数据目录（不引用原位置），内容相同的音频会自动去重。
- 音频时长必须在 **3~10 秒**：过短的自动在尾部补静音；过长的会弹出裁剪对话框，显示波形与建议区间，你确认后入库。
- **参考文本必填，且必须与音频逐字一致** —— v4 模型不允许空参考文本，文本对不上音色就会跑偏。
- **添加参考音频**：列表顶部有搜索框和「添加参考音频」，选文件 → 填语言与参考文本 → 确认即可；加完留在原地，方便连着补几条。列表里每条都能试听、删除。
- **导入角色**有两种方式，都在「选择角色」对话框里：
  - 「导入角色」：导入别人分享的 `.zip` 角色包；
  - 「从清单导入」：从训练切分产物导入，分别选择**清单文件**（`.list`）与**音频目录**，按**文件名**匹配，因此两者放在哪里都行。条数没有上限，但数量很多（超过 300 条）时会先列出"将导入多少条、各角色多少条"，确认后再开始。
- **导入后会按名称自动配好权重**（`千早爱音` ↔ `爱音-e15.ckpt`）。名称对不上时会留空，到「编辑角色」里手选一次即可。
- **角色列表只展示信息**：点卡片（或在「选择角色」里点角色名）打开「编辑角色」，名称、ID、星标、启用、权重、描述与参考音频都在那里。
- **角色 ID 可以直接改**（它同时是配置文件与 `game/vocal/<id>/` 目录的名字，改名时参考音频目录会一起搬走）。

## 三、队列与进度

配音任务**严格串行**执行（同时发起多个请求会互相干扰），分两档优先级：

1. **优先** — 默认是「测试」任务（x4 采样步数），用来快速试参数、试种子；
2. **常规** — 默认是「生成」任务（x32 采样步数），用来产出正式音频。

优先级是**每条任务自己的属性**，随时可以改：队列中任务的右侧（取消按钮左边）有一个箭头图标（上箭头=提升为优先，下箭头=降为常规），右键菜单里也有。运行中与已完成的任务不能再改档。

队列内部**按角色分组**，同一角色的任务连续执行，避免服务端反复重载模型。列表展示的顺序就是要发生的顺序：运行中 → 排队中 → 已结束（完成时刻从新到旧）。

进度与剩余时间是**估算**，也会随着实测数据自己变准 —— 同一档步数跑几次之后，「预计还需」会明显贴近实际。进度条走满只代表"该好了"，不代表一定结束。

「取消」对排队中的任务是直接撤下；对**正在推理**的任务是"这一条不要了" —— 推理没有中断接口，返回的结果会被丢弃，队列继续往下跑。取消后这条记录会从本句历史里移除，任务队列里仍能看到它被撤下。

## 四、配音编辑模式

**没打开配音工作台时，界面上不会出现任何配音痕迹。** 打开工作台后，当前场景卡上会出现一个划线麦克风：点它进入配音编辑模式（麦克风变实心），再点一次退回普通场景卡。

配音卡与普通场景卡**共享同一份文档**，两边的改动立刻互相可见。

- 配音卡是**只读编辑器**：它只负责「读场景 + 选语句」，任何编辑都回到普通场景卡完成。不过预览、语法高亮与 git 差异色块照常工作。
- 光标落在哪句对话上，**整行就会高亮**，下方操作台显示这一句的配置。WebGAL 的语句是一行一条，因此判定就是**行号精确匹配**；光标停在 `changeBg` 之类的演出语句上时，操作台只清空显示、不影响任何配置。
- **操作台分三段**：第一行「角色 / 语言 / 参考音频」，第二行「文本」，第三行「种子 / 温度 / 语速 / 高级设置」。数值都填在数字输入框里，鼠标悬停时框内出现步进箭头，刻度是固定的（温度、语速、重复惩罚 0.05，topK 1）。
- 「参考音频」点开的是该角色的音频列表，可以直接在里面挑一条或补一条。**没选角色时点它不会弹出东西** —— 参考音频是角色的东西。
- 「文本」**可以直接改**：改完再点测试或生成，送进模型的就是改后的文本，场景文件本身不受影响。选中一条历史记录时，回填的是它当初合成的文本。
- **种子默认由这条对话派生**：同一条对话每次打开都是同一个种子，所以「测试」与随后的「生成」用的是同一个种子，结果可以互相印证。想换种子有两个入口：「换一个随机种子」按钮，或者选中一条历史记录（连带回填它当时的参数）。
- **高级设置**里是 topK / topP / 重复惩罚 / 采样步数，最右边有「恢复默认」。采样步数只影响**正式生成**，跑一次测试不会把它带回 x4。
- 历史按**当前这一句对话**组织：换一句就换一批记录，批量清理也只作用于这一句。没能对齐到任何语句的残留记录会单独列在下方，可以一键清掉。
- 每条记录能试听、删除；右键菜单里还有应用、在文件夹中显示、导出音频、**复制种子**、以此参数重试、取消、删除。处理中的记录只保留「改优先级」与「取消」。
- 记录上的 **`响应` 是这一次请求实际花了多久**（音频本身有多长对配音没有参考价值，不展示）。
- 配音卡里 **`Ctrl+Z` 撤销、`Ctrl+Y` / `Ctrl+Shift+Z` 重做**也能用（例如刚应用的配音改了主意）；关闭自动保存时，`Ctrl+S` 把改动写回磁盘。
- **历史会存盘**：关掉配音卡、关掉选项卡、甚至重启 Ink，记录都还在。

## 五、配音工作台

配音工作台是**一个普通选项卡**（与场景文件、文本预处理、差异比较在同一条选项卡栏里），因此拖拽、关闭、切换的行为与其它选项卡完全一致。顶栏的配音按钮负责打开或聚焦它。

```
┌ 页头: 标题 · 服务状态                [启动服务] [帮助] ┐
├ 左栏: 启动方式 / 合成设置 ┬ 右栏: 队列 / 日志        ┤
└ 角色库 (占满剩余高度, 内部滚动)                      ┘
```

- **左栏分两页**：「启动方式」放整合包目录、启动方式与对应的解释器或命令；「合成设置」放默认语言。
- **整合包目录只有一个文件夹按钮**：还没选过时点击进入选择，已选过时点击在文件管理器中打开。
- 服务**启动中或已就绪**时，左栏「启动方式」页整体锁定 —— 改了也作用不到已经跑起来的进程上；停止服务后即可修改。
- 页头右上角是「启动服务」与「帮助」。启动过程中「停止服务」**始终可用**，路径填错时要能立刻停下。
- **右栏是运行状态**：「队列」页列出所有任务，并提供清理未被引用的缓存音频、清空已完成任务；「日志」页是服务输出，可以刷新与导出，启动失败时先看这里。
- **关闭工作台会一并停掉服务**（工作台就是这个功能的开关，没必要让推理进程继续占着显存与端口）。停止期间底部状态栏显示 `GSOV: 停止中…`，停完才收起。如果还有任务没跑完，关闭前会先问你一句 —— 退出的是配音模式，**历史记录不会丢**。
- GSOV 的连接状态只在**编辑器底部状态栏**显示，且只在工作台存在期间出现；不用配音功能时，界面上不会出现任何配音相关信息。

## 六、应用与移除

- **应用**：把生成结果移动到 `game/vocal/<角色 id>/<音频哈希>.wav`，并把该行的 `-vocal=` 指向它 —— 改动立刻出现在编辑器里，和你自己敲了这一行没有区别。是否落盘跟随**自动保存**设置：开启时立即写盘，关闭时只留脏标记等你保存。
- **移除**：只清除当前语句的 `-vocal=`，**不删除音频文件，也不清配音记录**（同一段音频可能被别的语句甚至别的场景引用）。
- 缓存音频的清理是**独立操作**：工作台里可以列出没有被任何场景引用的缓存文件，由你确认后删除。

## 七、重新打开场景卡

关闭场景卡后如果场景被编辑过，重新打开时：

1. 先检测磁盘文件是否被外部修改。若是，会请你裁决：
   - **保留编辑器当前内容**：把编辑器里的这一份**写回磁盘**，此后以它为准（不会再来问第二遍）；
   - 丢弃当前内容并加载磁盘内容；
   - 用 git 合并（打开独立页面）；
   - 另存为副本后再加载磁盘内容；
   - 按 `Esc` 表示暂不决定：谁也不动，但同一个磁盘版本不会再反复弹窗。
2. 再把配音记录**重新对齐**到当前的对话列表：完全匹配得上的自动归位，对不上的会明确列在"未能对齐"里，不会猜着配到别的对话上。

因此：**场景改得越多，能自动对齐的记录越少**，但已经写进脚本的 `-vocal=` 与磁盘上的音频文件永远不受影响。

## 八、常见问题

- **启动失败**：先看工作台的运行日志。常见原因是整合包路径不对、端口被占用，或者外部 Python 缺少依赖（`ModuleNotFoundError` 时改用整合包运行时）。
- **报错说找不到 NLTK 资源**（例如 `Resource averaged_perceptron_tagger_eng not found`）：整合包环境里缺数据文件，不是 Ink 的问题。在整合包所用的 Python 环境里执行 `python -m nltk.downloader averaged_perceptron_tagger_eng`（按报错里的资源名替换）后重试。记录里的报错**点一下就能看到全文**，并附有这条命令。
- **生成很慢**：确认用的是 CPU 还是 GPU 推理。CPU 上 x32 的一句中长对话可能要数分钟 —— 建议先用 x4 试好参数与种子，再正式生成。
- **音色不对**：检查参考文本是否与音频逐字一致；检查参考音频是否在 3~10 秒、人声是否清晰。
- **某句话没有自动匹配到角色**：匹配依据依次是「角色名 / 角色 ID 完全相同」→「立绘引用」→「名称包含关系」（`千早爱音（教室）`、`爱音` 都能对上 `千早爱音`）。既不相等也不互相包含的称呼（例如「小爱」）**不会**被猜着匹配，手动选一次即可，这个场景会记住。也先确认该角色在「选择角色」里是勾选状态。
- **找不到某条配音记录**：记录跟着**场景文件**走，换了项目目录或移动了场景文件就会读不到。另外场景改动较大时，个别记录可能落在"未能对齐"里，重新对齐或清理即可。
