# GPT-SoVITS 配音工作流

Ink 的配音功能把 **GPT-SoVITS (GSOV) v4** 的推理接入到场景编辑流程里: 在总控台配置服务与角色, 在场景卡的配音模式里逐句生成、试听、应用。

> 当前仅支持 **v4 模型**, 且仅支持 **本地部署** (由 Ink 自己拉起 GSOV 进程)。

## 一、准备工作

1. 准备一份 GPT-SoVITS v4 整合包 (含 \`api_v2.py\` 与 \`runtime\\python.exe\`)。
2. 在总控台顶部填写**整合包路径**, Ink 会自动探测运行时并给出默认启动参数。
3. 需要时切换启动方式:

| 启动方式 | 适用场景 | 说明 |
| --- | --- | --- |
| 整合包内置运行时 | 默认, 推荐 | 使用 \`runtime\\python.exe\`, 依赖自包含, 会自动加 \`-I\` 隔离 |
| 外部 Python | 自建 conda / 系统环境 | **不会**加 \`-I\`: 隔离模式会屏蔽用户级 site-packages, 而 \`click\` 等依赖常装在那里 |
| 自定义命令 | 自己写 bat/ps1 启动脚本 | Ink 只负责启动、收集日志与退出时收尸, 参数完全由你决定 |

4. 点击「启动」, 状态栏与总控台顶部会显示 \`启动中…\` / \`就绪\`。首次启动需要加载模型 (数十秒)。

## 二、角色

角色 = **GSOV 模型 + 参考音频**组合。

- **参考音频**会被拷贝进 Ink 的用户数据目录, 不引用原位置; 同内容音频自动去重。
- GSOV 要求参考音频时长在 **3~10 秒**:
  - 过短: 自动在尾部补静音 (静默处理);
  - 过长: 弹出裁剪对话框, 展示波形与自动建议区间, 由你确认后由后端裁剪。
- **参考文本必填**, 且必须与参考音频**逐字一致**。v4 模型在使用声码器时不允许空参考文本, 文本不符会让音色跑偏。
- **标签**目前仅用于 Ink 内部整理, 后续版本会承载更多语义。
- 参考音频支持试听; 角色列表支持搜索、新建、导入/导出 zip。

## 三、队列

配音任务**严格串行**执行: GSOV 后端是单进程单 worker, 并且持有全局的参考音频缓存, 并发请求会互相干扰。

队列分为三类, 按此优先级执行:

1. **立即队列** — 测试任务 (x4 采样步数), 用于快速试参数与试种子;
2. **普通队列** — 生成任务 (x32 采样步数), 用于产出正式音频。

两个队列内部都**按角色分组**: 同一角色的任务连续执行, 避免服务端反复重载模型 (切换权重需要重载底模, 代价很高)。

进度与剩余时间是**估算**: 用已经完成过的任务实测校准, 并区分测试/生成两套系数。第一次任务通常偏慢 (服务端需要建立参考音频缓存)。

## 四、场景卡配音模式

在场景选项卡上点击麦克风图标即可进入配音模式 (图标带斜杠表示未启动)。配音卡与普通编辑卡**共享同一份文档**, 因此修改会立即互相可见。

- 光标落在对话上时, 下方操作台显示该句的配音配置; 移动光标会切换语句, 但**操作台高度固定**, 不会造成编辑器跳动。
- 角色会依据场景中的 \`-figureId\`、角色名与别名**静默匹配**; 旁白会沿用同场景上一条旁白所选的角色。匹配结果可以手动更改, 更改后会作为该场景的覆盖被记住。
- **配音参数的编辑永远不被禁用**: 一旦你改动了任意参数, 该配置就被视为**新的配置**, 不会影响已有历史记录。此时「测试」「生成」会创建新任务, 「应用」按钮不可用, 「移除」按钮的含义是**移除当前语句的配音引用** (与历史无关)。
- 右键历史记录可以应用、在文件夹中打开、取消、删除, 以及批量删除。

## 五、应用与移除

- **应用**: 把生成结果移动到 \`game/vocal/<角色 id>/<音频哈希>.wav\`, 并把该行的 \`-vocal=\` 指向它。若全局开启了自动保存, 会同时写盘; 否则你需要在普通编辑卡里保存。
- **移除**: 只清除当前语句的 \`-vocal=\`, **不删除音频文件, 也不清历史**。因为同一段音频可能被其他语句甚至其他场景引用 (你可能会复制带配音的对话行)。
- 缓存音频的清理是**独立操作**: 总控台可以列出未被任何场景引用的缓存文件, 由你确认后删除。

## 六、重新打开场景卡

关闭场景卡后如果场景被编辑过, 重新打开时 Ink 会:

1. 先检测磁盘文件是否被外部修改。若是, 会先请你裁决:
   - 保留编辑器当前内容;
   - 丢弃当前内容并加载磁盘内容;
   - 用 git 合并 (打开独立页面);
   - 另存为副本后再加载磁盘内容。
2. 裁决完成后, 再把历史记录**重新对齐**到新的对话列表: 先按「对话者 + 内容」精确匹配, 再按内容做保序匹配。无法匹配的记录会明确列出, 不会猜测性地错配到别的对话上。

因此: **改动越大, 能对齐的历史越少**, 但已经写进脚本的 \`-vocal=\` 与磁盘上的音频文件永远不受影响。

## 七、常见问题

- **启动失败**: 查看总控台日志面板。常见原因是整合包路径不对、端口被占用, 或者外部 Python 缺少依赖 (\`ModuleNotFoundError\` 时改用整合包内置运行时)。
- **生成很慢**: 确认是 CPU 还是 GPU 推理。CPU 上 x32 的一句中长对话可能需要数分钟, 建议先用 x4 测试确认参数与种子, 再生成。
- **音色不对**: 检查参考文本是否与音频逐字一致; 检查参考音频是否在 3~10 秒且人声清晰。
- **生成结果有电音/杂音**: 提高采样步数, 或调整温度与重复惩罚。
